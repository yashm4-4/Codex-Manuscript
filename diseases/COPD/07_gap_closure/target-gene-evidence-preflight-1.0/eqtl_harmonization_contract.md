# Frozen eQTL allele-harmonization contract

Applies before any risk/expression concordance evaluation. Inputs are only frozen `fine-mapping-input-resolution-1.0/tables/gwas_only_risk_direction.tsv.gz` rows with `VERIFIED_GWAS_SIGNED_CONTRAST_NOT_CAUSALITY`, V1 candidate GRCh38 `chrom:pos:REF:ALT`, and V1 GTEx v10 Lung exact significant-pair records. Keep source row, accession, phenotype stratum, original and normalized identity, source beta/OR/SE, and provenance hash. A/B/C GRCh37 must be converted by a **unique** reference-checked allele-aware chain/normalization to GRCh38; the Catalog harmonized A file is auxiliary and never substitutes for the native signed row. The already verified GWAS risk allele is an effect-contrast label, not a causal-allele claim.

## Deterministic rules, in order

1. Reject missing/unverified signed GWAS direction, invalid or symbolic alleles, unresolved duplicate identity, or an unverified source REF/ALT convention. Do not infer sign from REF, ALT, frequency, model score, LD or P value.
2. Require exact chromosome, 1-based position and normalized REF/ALT on the **same verified build**. Validate original and converted REF against the matching reference FASTA. For indels, trim/left-normalize against the reference and demand a unique allele-resolved mapping; retain the original representation. Never join by rsID alone.
3. Evaluate forward and reverse-complement representations of the entire REF/ALT pair. A strand complement is accepted only if the genome reference and unique lift-over prove that representation; do not use complementation to rescue a contradictory reference.
4. Map GWAS effect/other alleles to the resolved b38 REF/ALT pair. An effect/non-effect allele swap reverses the sign; a strand complement alone does not. Record `same_alt`, `reversed_ref`, or `complement_verified` plus signed multiplier `+1` or `-1`. The source disease-increasing allele must map uniquely to REF or ALT, including when source beta is negative.
5. A/T and C/G palindromic SNVs are **unresolved** unless the sequence/reference and an independent, unique allele-aware cross-build map resolves the orientation. Frequency similarity alone is not an orientation proof. If ambiguity remains, exclude the row from direction analysis, even when coordinate and rsID agree.
6. GTEx v10 `chr_pos_REF_ALT_b38` is the exact pair key. Its `slope` is per **GTEx ALT** allele for normalized expression. Preserve the versioned Ensembl gene ID and a versionless ID for joins; gene symbols are display only. Do not join two genes on name alone. Treat multiallelic ALT records separately.
7. Fail closed on unmatched, multiply mapped, REF-discordant, strand-ambiguous, conflicting duplicate, unknown effect-allele, or missing-slope rows. Emit an explicit reason and keep all denominators. A missing significant GTEx row means **no exact significant pair observed**, not no eQTL.

Output schema for future execution: `candidate_record_id, phenotype_stratum, gwas_track, gwas_source_row, source_build, source_identity, b38_identity, conversion_method, reference_validation, palindromic_status, source_effect_allele, source_other_allele, disease_increasing_allele_b38, gtex_variant_id, versioned_gene_id, gtex_alt_slope, gtex_slope_se, orientation_class, multiplier, harmonization_status, exclusion_reason, source_sha256`. Freeze all rule text and software/chain/reference hashes before computing concordance. No such output is calculated in this stage.
